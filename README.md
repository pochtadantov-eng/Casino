# Stars Casino — Telegram Mini App

NestJS + grammY + PostgreSQL. Баланс пополняется Telegram Stars (XTR). Подарки — этап 2.

## Игры
| Игра | Механика |
|---|---|
| 🚀 Ракета | Общие раунды для всех: 5 секунд приёма ставок → полёт → краш → пауза → следующий раунд (таймлайн считает сервер, `src/games/engines/rocket-schedule.ts`, точка краша выводится из `ROCKET_SECRET` и открывается только после краша). Нужно успеть «Забрать» до краша; есть авто-вывод (работает и если игрок закрыл приложение). Рядом ставят боты (одинаковые у всех, зависят от номера раунда): ✓ — забрал, ⏳ — ждёт, ✕ — проиграл. |
| 💣 Мины | Поле 5×5, 3–24 мины, каждая открытая клетка повышает икс; RTP 85% (`MINES_EDGE`), поэтому звёзды собирать сложнее, чем в остальных играх. |
| 🏗 Башня | Игра на мастерство: домик раскачивается на верёвке, игрок тапает по экрану, когда он над зелёной зоной на крыше башни. Качание и проверку тапа считает сервер (`src/games/engines/tower.ts`). С высотой качание быстрее, а зелёная зона уже; допуск по времени ±40 мс. Попал — домик встаёт (почти по центру зоны), промахнулся — падает. Иксы: x2 на 5-м этаже (розово-белый домик), x4.97 на 10-м, дальше «космос» до ≈x12.9. |
| 🕊 Чайка | Чайка летит над 3 детьми и хватает одного; угадай, кого она **не** заберёт. 12 шагов, икс растёт с каждым. |

RTP игр 92% (`HOUSE_EDGE`; Мины — 85%, `MINES_EDGE`; Башня — на мастерство) (см. `src/games/engines/types.ts`); проверяется симуляцией в `test/engines.spec.ts`.
Исход каждого раунда определяется сидом до первого хода, а лимит выплаты (`MAX_PAYOUT`) ограничивает риск.

## Честность (provably fair)
Перед раундом игрок видит `sha256(serverSeed)`, после — сам `serverSeed`. Все случайные числа:
`HMAC_SHA256(serverSeed, clientSeed:nonce:i)` (`src/fair/fair.ts`) — любой раунд можно переиграть.

## Запуск
```bash
cp .env.example .env        # BOT_TOKEN, WEBAPP_URL, ADMIN_IDS, ROCKET_SECRET, DATABASE_URL ...
docker compose up -d --build   # база + всё казино (API, бот, Mini App) на :3000
npm install && npm run setup:bot   # проверка токена и Stars-платежей, команды бота, кнопка Mini App
npm test
```
Без Docker: `docker compose up -d db && npm install && npm run build && npm start`.

### Подключение настоящего пополнения Stars (чек-лист)
1. @BotFather → `/newbot` → токен в `BOT_TOKEN`. Для Stars (XTR) платёжный провайдер не нужен.
2. Сервер с публичным **HTTPS** (VPS + Caddy/nginx, Render, Fly.io…) на порт 3000; адрес — в `WEBAPP_URL`.
3. @BotFather → `/mybots` → ваш бот → Bot Settings → Configure Mini App → тот же URL.
4. В `.env`: `ADMIN_IDS` (ваш Telegram id), свой длинный `ROCKET_SECRET`, `CHEST_UNLIMITED=0`, `DEV_AUTH=0`, надёжный пароль базы.
5. `docker compose up -d --build`, затем `npm run setup:bot` — должны быть зелёные галочки (токен, команды, кнопка, счёт на Stars).
6. Откройте бота → «Играть» → «+» у баланса → оплатите 50 ⭐ → баланс вырастет за пару секунд; в профиле появится запись. Тестовый платёж возвращается командой `/refund <charge_id>` (id виден в чеке Telegram и в логах).
Страница GitHub Pages (`scripts/build-pages.mjs`) — это **демо** без сервера: пополнение там игрушечное. Настоящие платежи работают только когда Mini App открыт с вашего сервера.

Mini App нужен публичный HTTPS (ngrok / cloudflared / домен): укажите его в `WEBAPP_URL` и в @BotFather → Mini App.
Локально без Telegram: `DEV_AUTH=1` и открыть `http://localhost:3000/?dev=123` (**только для разработки**).

## Деньги
- Депозит: кнопка «+» у баланса / «Пополнить» в профиле (шторка с суммами 50–2500 и своей суммой, `MIN_DEPOSIT`..`MAX_DEPOSIT`) или `/deposit [сумма]` в боте → инвойс в XTR → `pre_checkout_query` (повторная проверка пользователя, суммы и валюты) → `successful_payment` → зачисление (идемпотентно: уникальный индекс по `telegram_payment_charge_id`). Payload счёта `dep:<userId>:<сумма>` сверяется с реальным плательщиком и суммой платежа; если не совпало — платёж не зачисляется, админам уходит уведомление. После оплаты мини-апп опрашивает баланс и показывает «+N ⭐ зачислено».
- Возвраты: `/refund <charge_id>` (только `ADMIN_IDS`) возвращает Stars плательщику через `refundStarPayment` и снимает сумму с баланса (не ниже нуля: если Stars уже сыграны, снимается остаток); событие Telegram `refunded_payment` обрабатывается так же. Бот отвечает на обязательные `/paysupport` и `/terms`.
- Вывод подарком: в профиле «🎁 Подарком» → выбор подарка из `getAvailableGifts` (без Premium-only и распроданных) → цена списывается с баланса (цена подарка + `GIFT_FEE_PCT`, не больше `GIFTS_PER_DAY` в сутки) → бот делает `sendGift`, и подарок приходит игроку в чат с ботом как настоящий подарок Telegram (если Telegram отказал — Stars возвращаются, админам уходит уведомление). **Подарок оплачивается из баланса Stars самого бота** (его пополняют платежи игроков, но следите, чтобы он не уходил в ноль). Игрок должен хотя бы раз написать боту. Обычные подарки нельзя обратно обменять на Stars. Уникальные NFT-подарки Bot API отправить не может: для этого нужен подключённый бизнес-аккаунт (`transferGift`) — это отдельный этап.
- История пополнений/выводов/бонусов в профиле (`GET /api/cash`).
- Вывод подарка идёт через очередь `gift_orders`: Stars списываются сразу, в истории профиля запись «⏳ Подарок отправляется…», через случайные `GIFT_DELAY_MIN_SEC`–`GIFT_DELAY_MAX_SEC` (по умолчанию 15–20 с) бот-воркер (каждые 3 с) действительно делает `sendGift`, и запись становится «✅ Подарок отправлен в чат». Если Telegram отказал — Stars возвращаются, запись «❌ Подарок не отправлен», игроку и админам приходит сообщение. Статус «отправлен» ставится только после настоящей отправки.
- Личный режим «визуальных подарков» (для связки с собственным PampGram): если id игрока есть в `VISUAL_GIFT_USER_IDS` и задан `VISUAL_GIFT_TOKEN`, вывод подарка и приз сундука не вызывают `sendGift` — баланс списывается как обычно, бот пишет «Подарок придёт в течение минуты», а подарок кладётся в очередь `visual_gifts`. Клиент PampGram опрашивает `GET /visual/pending?uid=…&token=…` и подтверждает `POST /visual/ack?…&ids=…` (403 для чужих id и без токена) и через `VISUAL_GIFT_DELAY_SEC` рисует подарок локально, у себя на устройстве. Остальным игрокам по-прежнему приходят настоящие подарки.
- Ежедневный сундук (вкладка «Бонусы»): раз в 24 ч рулетка с призами 15 / 25 / 50 / 100 / 150 / 500 / 1000 ⭐ или настоящий подарок Telegram (≈25 / 50 / 100 ⭐). Приз выбирает сервер (`src/wallet/chest.ts`: шансы и суммы настраиваются там, `chestEv()` — ожидаемая выдача), телефон только показывает рулетку. Звёзды зачисляются сразу; когда выпадает подарок, бот сам делает `sendGift` и подарок **прилетает игроку в чат с ботом** (оплачивается из Stars бота). Если бот не смог отправить (пустой баланс бота, игрок не писал боту), подарок попадает в очередь `user_gifts`, админам приходит уведомление: отправьте вручную и отметьте `/sent <id>` (список `/gifts`). `DAILY_BONUS=0` выключает сундук. Для тестов: `CHEST_UNLIMITED=1` разрешает открывать сундук без ожидания 24 ч всем, а `ADMIN_IDS` могут это всегда (**это бесплатные Stars — не оставляйте включённым на проде**).
- Все изменения баланса идут через `WalletService.apply` в транзакции, с записью в `transactions`; баланс не может уйти в минус.
- Вывод: заявка (`/withdraw`, кнопка «Вывод») → админ из `ADMIN_IDS` делает `/pending`, `/approve <id>` или `/reject <id>` (отказ возвращает деньги).
  **Выплата Stars игроку Bot API напрямую не поддерживает** — сейчас одобрение только фиксирует заявку, а перевод делается вручную.
  Автоматическая выплата возможна через подарки (`sendGift`) — это этап 2.

## Структура

## Перед запуском в проде
- Правила Telegram: проверьте допустимость использования Stars в азартных играх — иначе бот и возможность принимать Stars могут быть заблокированы.
- Лицензия/юрисдикция на азартные игры, 18+, KYC/AML, ответственная игра — на стороне владельца.
- Rate limiting, webhook вместо long polling, бэкапы БД, мониторинг, лимиты на игрока.

## Башня — экономика (важно)
Исход Башни зависит от точности тапа, а не только от случайности, поэтому RTP зависит от навыка игрока.
`node scripts/tower-rtp.mjs` (после `npm run build`) показывает RTP для разной точности: обычный игрок (±150–300 мс) возвращает 2–55% ставки,
хороший (±80 мс) около 90% при выходе на 1-м этаже, а эксперт (±40 мс) или бот выигрывают у казино. Перед запуском на деньги: ограничьте ставку и макс. выплату
для этой игры (в «космосе» выплаты у ботов с идеальным таймингом огромны — режьте `MAX_PAYOUT` и лимитируйте раунды), следите за аномально ровным таймингом (признак бота) и пересчитайте лесенку (`TOWER.ladderGrowth`, `TOWER.spaceGrowth`).

## Админ-бот (отладка/демо)

Чтобы в реальном времени видеть скрытое состояние твоего раунда:

**В мини-аппе (демо-режим на GitHub Pages):** открой с `?debug=1` в адресе, или в консоли браузера `localStorage.setItem('nova.debug','1')` и перезайди. В углу карточки игры появится красная рамка с крэш-точкой ракеты, координатами мин, окном попадания башни и т.д.

**На живом сервере:** добавь свой Telegram ID в env `ADMIN_IDS=123456789,...`. Эндпоинт `GET /api/admin/peek/:game` вернёт `{ debug }` с внутренностями твоего активного раунда (только для админов из `ADMIN_IDS`, обычный игрок получает 403). Твой внешний бот/скрипт может опрашивать его и показывать подсказки. Клиентскую панель включаешь так же: `localStorage.setItem('nova.debug','1')` — она подтянет debug из того же API-ответа.

Другие игроки ничего не видят: обычный `view` остаётся без секретов, `debug` отдаётся только для админов.
